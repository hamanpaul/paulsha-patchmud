# 怎麼玩 PatchMUD（給沒寫過程式的你）

一句話：**一款「修東西」的回合制遊戲**。每一關給你一台「壞掉的小機器」（一小段程式），機器有個毛病。你的任務——找出毛病、把它修好。修好就過關。

## 你的目標

畫面上有個數字叫「**待辦**」，就是「還沒解決的問題數」，開場通常是 **1**。把它降到 **0**，這關就乾淨了。

## 一回合怎麼玩

像大富翁那樣一回合一回合輪。**每回合只做一件事**，做完換下一回合。你有回合數上限（例如 6 回合）跟時間上限，所以別亂逛。每回合打一個動作，最後**空一行送出**（想直接收場按 `Ctrl-D`）。

| 你想做的事 | 打這個關鍵字 |
|---|---|
| 看這關有哪些檔案 | `LOOK` |
| 仔細看某個檔的內容 | `INSPECT <檔名>` |
| **動手修** | `PATCH`（下一行起用 `PATCH:` 附上你的修改） |
| 試跑測試看紅綠 | `RUN_TEST` |
| 宣布「我修完了」 | `COMMIT` |

## 怎麼算贏

送出修理後，遊戲會自動跑一批測試檢查你修得對不對。修對了，待辦歸 0、戰場乾淨。你 `COMMIT` 後進最終評分：

- **通關 / 未通關**
- **一個分數（最高 100）**——修得越乾淨、越省回合，分越高。

## 這遊戲的靈魂：藏起來的考題

有一批考題是**藏起來、你看不到的**。

意思是：**你看得到的測試過了，不代表真的修好。** 藏起來的考題會抓你有沒有漏掉狀況。所以不能只讓表面過關——要真的搞懂毛病。（這就是為什麼在 versus 裡，兩個 AI 明明都「修好了」，其中一個卻沒過關：它被藏起來的考題抓包了。）

## 你適合哪種玩法

「動手修（`PATCH`）」那一步，實際上要**編輯程式碼**——這是遊戲的本質（它本來就是拿來考「會不會修程式」的）。

- **想親自下場**（願意照抄、碰一點程式）→ 玩 `patchmud play <關卡>`。開場會有白話規則，跟著提示打即可。
- **零程式、當裁判看熱鬧**（多數非程式背景的人適合這個）→ 不用自己修，改成看 AI 模型去修、你當裁判：`patchmud versus <關卡> --models sonnet,haiku`——兩個模型打同一關，並排看誰修得好、誰只是表面糊弄。

## 兩條路的一行指令

```bash
patchmud play input-validation-v1        # 自己下場（開場有白話規則）
patchmud versus input-validation-v1 --models sonnet,haiku   # 當裁判看 AI 對決（需登入）
```

> 可玩的關卡在 `decks/pilot-v1/`（如 `input-validation-v1`、`parser-edge-v1`），還有用出題模組產的 `decks/authored-demo/discount-clamp-v1`。出題方式見 [`docs/authoring/README.md`](authoring/README.md)。
