## Why

The frozen pilot deck saturates on one-file repairs and cannot answer the user's concrete Luna max versus Gemini Flash high selection question. The user explicitly requested a controlled, JEV-judged engineering benchmark with reusable historical baselines and a persistent detailed model-score report.

## What Changes

- Add grouped base/target CLI profiles and explicit native effort without changing legacy commands.
- Add eighteen engineering cases across six categories and three reasoning depths, plus pilot and frozen-suite provenance.
- Add pinned JEV quality scoring over controlled execution evidence; preserve objective facts and service errors separately.
- Add immutable run archives, compatible baseline reuse and a locked Markdown report in the user's configuration directory.

## Capabilities

### New Capabilities

- `jev-model-scoring`: controlled profile evaluation, engineering cases, typed JEV scoring, historical comparison and persistent reports.

### Modified Capabilities

None. Existing ranked metrics retain their original interpretation; the new scoring profile explicitly permits JEV judgments.

## Impact

New scoring modules and packaged fixtures, additive CLI entry point and adapter settings, tests, documentation and canonical agent policy. No Cortex/Hippo/session-health runtime dependency. Related issues #21, #37 and #38 inform boundaries but are not claimed fully resolved by this feature.
