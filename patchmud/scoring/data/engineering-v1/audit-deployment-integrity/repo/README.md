# Deployment integrity audit fixture

This synthetic packet describes a two-node `payments-api` rollout.  The
control plane calls a manifest complete when it accepts the desired state, so
the dashboard label is weaker than a process identity observation.  The
initial public records intentionally use a mutable tag; staged messages later
add node and registry evidence with different coverage.

The audit is read-only.  It must preserve the distinction between a selected
image, a successful pull, and a process that actually started that image.
